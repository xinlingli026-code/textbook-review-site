# 评估：带 skill vs 不带 skill

同一道任务、同一份教材 PDF、同一份站点副本，唯一差异是是否加载 `textbook-review-site` skill。

- **任务**：把教材 Chapter 3 §3.8（Exponential Growth and Decay）的习题录入复习站，中英双语，含分步解法，做渲染校验，**不发布**。
- **对照组起点**：`projects/_work/eval-base/`（27 文件的仓库副本）
- **实验组起点**：`projects/_work/eval-prod/calculus-ch2-review/`
- **真实仓库**：全程零改动，两个实验都没推送、没发布。

> 本文件只记录**方法与指标**。两份完整报告里的官方答案转写属于 Cengage 版权内容，
> 刻意不复制到本公开仓库。

## 结果总览

| | 带 skill | 不带 skill |
|---|---|---|
| 3.8 习题 | 22 题（中英各一份内容层） | 22 题（中英各一份内容层） |
| 课堂例题（教材例 1–4 + 应用项目） | 未收录 | **+5** |
| 记忆卡 / 易错点 / 公式式子（Ch3 增量） | +7 / +5 / +8 | **+11 / +7 / +12** |
| 官方解答转写（奇数题） | 11 / 22 | 10 / 22 |
| 官方答案来源 | 详解手册扫描件转写 | 教材**书末 Appendix I 奇数题答案册** |
| 小节排序（3.8 落在 3.7 与 3.9 之间） | 正确 | 正确 |
| README 计数同步 | 已更新 | 已更新 |
| 章节合并位置 | 与既有约定一致 | 与既有约定一致 |
| **中文正文被误排成公式** | **4 处（货币 `$` 触发）** | **0 处** |
| 临时产物 | 残留 1 个测试页在仓库根目录 | 已清理 |

## 带 skill 真正带来的增益

1. **前提核对前置**。两边都独立发现了「用户说的 3.8 = 逆三角函数求导」与教材冲突
   （Stewart 8e 里 3.8 = 指数增长与衰减，逆三角求导在 3.5）。带 skill 的那版在
   `SKILL.md` 步骤 2 明确要求核对，并在交付里显式标注差异，判定依据可回溯。
2. **收录边界可控**。skill 把「是否收录官方解答」设成必须问的版权边界项，
   并且明确「只有用户要求收录时才去翻扫描件详解手册」——这条直接决定了是否要付出
   「定位 + 逐页 OCR + 人工转写」的整节成本。
3. **方法可复用**。带 skill 的产出直接沉淀成了本仓库的四个脚本（数据生成、DOM 校验、
   PDF 渲染、页眉 OCR），下一次换书换科目可以直接复用；不带 skill 的那版脚本是一次性的。

## 不带 skill 那版反而更好的地方

1. **官方答案的取用路径更省**。它发现教材**书末**就有奇数题答案册（Appendix I），
   一页 OCR 拿到 3.8 全部奇数题答案，不必去啃详解手册的连续解答页。
   → 已把「先找书末答案册，再考虑详解手册」写进 skill。
2. **更密的内容层**。例题、记忆卡、易错点、公式条目都更全（见上表）。
3. **踩出了本站最大的渲染坑**。货币符号 `$` 与数学定界符配对，把整段中文排成公式
   （KaTeX 用 `cjk_fallback` 渲染，字形与间距都错）。它给出可用解法
   `$\text{\$}1000$`，并指出 `\textdollar` 在 KaTeX 0.16.9 不被支持。
   → 已把这条坑、检测方法写进 `references/site-architecture.md`，
   并给 `scripts/verify-dom.js` 加了 `cjkFormula` 指标（> 0 即退出码 1）。

## 对 skill 的迭代（每次评估后都回写并复跑 lint）

| 轮次 | 依据 | 改动 |
|---|---|---|
| 1 | 详解扫描件定位 + 转写一节的成本接近重做一遍题 | 步骤 4 从「默认对照官方解答」改为「按需对照」 |
| 2 | 用户给的节号/页码可能与教材不符 | 步骤 2 增加前提核对，并要求显式标注差异 |
| 3 | 页码偏移不能跨书沿用 | `pdf-extraction.md` 要求**每个文件单独实测偏移** |
| 4 | 入口页引用可能指向不存在的文件（404 不会自己暴露） | 步骤 5 增加「先确认目标文件存在于该语言目录」 |
| 5 | 临时产物会被 `git add -A` 带走 | 步骤 7 要求临时产物写到仓库目录之外 |
| 6 | README 数字手算易错 | 步骤 9 + `site-architecture.md` 的 README 计数清单（脚本重算） |
| 7 | 货币 `$` 与数学定界符配对 | 步骤 6 + `site-architecture.md` 专节 + `verify-dom.js` 的 `cjkFormula` |

## 一句话结论

skill 带来的最大价值是**把「前提核对 / 收录边界 / 成本控制」变成默认动作**，并让整套流程可复用；
但它**不能替代领域判断**——不带 skill 的那版反而找到了更省的官方答案来源、更密的内容层，
还踩出了本站最隐蔽的渲染坑。所以 skill 里必须持续收录这些「实测踩过的坑」，
否则它只是流程说明，而不是经验库。
